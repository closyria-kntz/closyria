# Chantier 4 « Alertes » — plan de travail

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prévenir l'utilisatrice par notification (et « une » / page « Nouvelles ») quand sa taille revient, quand son prix visé est atteint, et chaque jour des baisses de prix, soldes et promos de ses envies.

**Architecture:** Chaque écriture d'article (import, capture, vérification de fiche) ajoute déjà une ligne `product_history` ;
le worker compare cette ligne à la précédente et crée des `alert_events` pour les envies suivies. Une file d'envoi
pg-boss applique les règles (anti-doublon, calme de nuit, plafond, résumé) et envoie des notifications Web Push (VAPID)
aux appareils abonnés. Un planificateur revisite toutes les 6 h les articles suivis des boutiques non importées.

**Tech Stack:** Hono + zod-openapi, Drizzle (migration suivante libre), pg-boss, `web-push` (worker), Next 16 (service worker `public/sw.js`), next-intl, Vitest, Playwright + axe.

**Spec:** `docs/specs/2026-11-14-alertes.md`

## Global Constraints

- Textes : « M'alerter », « Préviens-moi sous … € », « Ta taille est revenue », « La {article} est de retour en {taille} chez {boutique} », « La {article} est à {prix} (tu visais {seuil}) », « {n} baisses de prix dans tes envies », « Les soldes commencent {jour} », « {boutique} est en promo », « Nouvelles », « Activer les notifications », « Crée ton compte pour recevoir tes alertes », « Suivi : taille {t} · vérifié il y a {n} min », « Suivi impossible pour cette boutique », « Suivi en pause ».
- Baisse « réelle » : au moins 5 % **ou** 5 € (500 centimes) sous le prix précédent.
- Calme : aucune notification entre 22 h et 8 h, heure `Europe/Paris` ; envoi à 8 h.
- Résumé : une fois par jour à 18 h par défaut (heure réglable 7–22 h), heure `Europe/Paris`.
- Plafond : 5 notifications immédiates par personne et par jour civil (Paris) ; au-delà → résumé.
- Anti-doublon : « taille revenue » au plus 1 fois / 24 h par (personne, article, taille) ; prix visé : 1 fois tant que le prix ne repasse pas au-dessus du seuil ; une baisse n'entre qu'une fois dans le résumé.
- Revisite des articles collés (boutique non importée) : toutes les 6 h tant qu'ils sont suivis ; jamais pour boutiques bloquantes / grandes enseignes ; via les files et garde-fous existants (file Shopify, ralentissement, robots).
- Abonnement aux notifications : compte requis (`user.is_anonymous = false`) ; invitée → `403 { error: "account_required" }`.
- Secrets VAPID : `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`https://closyria.com`) dans `/etc/closyria/<env>.env`, validés au démarrage (worker et API) ; jamais dans le dépôt.
- Mêmes règles que les chantiers précédents (jetons Boudoir, clair/sombre, axe, 44 px, code anglais / interface française, Zod aux frontières, schémas partagés dans `packages/shared`, commits `closyria-kntz` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, ports interdits, pas de `pkill -f`/`git stash` nu, jamais deux suites e2e en même temps).

## Review Focus

1. Un import horaire réécrit 1 800 articles sans changement : aucun événement d'alerte (seules les vraies transitions comptent) — test en Task 2.
2. Une taille qui clignote (disparue puis revenue en 10 min) : une seule alerte par 24 h — test en Task 2.
3. Alerte née à 23 h 30 : envoyée à 8 h le lendemain, pas avant, et compte dans le plafond du jour d'envoi — test en Task 4.
4. Navigateur qui a retiré l'abonnement (réponse 404/410) : abonnement supprimé, pas de nouvel essai — test en Task 4.
5. Article déplacé vers un autre profil ou retiré de ses envies (passé « Commandé », supprimé) : plus d'alerte — test en Task 2.
