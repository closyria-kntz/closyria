# Offrir (partie 2b) — plan de travail

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sur le lien d'une liste ouverte aux cadeaux, les amies réservent (seules ou à plusieurs) ce qu'elles offrent ; la fondatrice n'en voit rien, sauf un avertissement sans nom avant d'acheter un article réservé, et découvre les offrantes en marquant « Reçu en cadeau ».

**Architecture:** Une table `wishlist_gifts` à côté de `wishlist_opinions`, la même reconnaissance d'amie (`wishlist_opinion_devices`, prénom normalisé + empreinte de clé d'appareil) et le même lien public. Les routes publiques `/api/shared/{token}` exposent l'état des cadeaux ; les routes de la fondatrice ne l'exposent jamais, sauf `gift-check` (des ids, sans prénom) et `items.gift_from` (prénoms figés à « Reçu en cadeau »).

**Tech Stack:** Hono + `@hono/zod-openapi`, Drizzle/PostgreSQL (migration SQL versionnée), Zod partagé (`packages/shared`), Next 16 (`apps/web`), next-intl (`packages/i18n/messages/fr.json`), Vitest (intégration API), Playwright + axe (`e2e`).

**Spec:** `docs/specs/2026-11-09-offrir.md`

## Global Constraints

- Code en anglais, interface et documentation en français ; textes exacts de la spec § 3 et § 4 (ex. « Je lui offre », « Je l'offre », « Réservé par {nom} », « Offert par {noms} », « Je participe », « Tu lui offres », « Tu participes », « Me retirer », « Tu t'es retirée · Annuler », « Sa taille : {taille} », « Taille non précisée », « {nom} vient de le réserver », « {prénom} l'a retiré de sa liste », « {prénom} l'a pris elle-même », « Déjà offerts », « Offert ✓ », « Attends un peu 🎁 », « Quelqu'un a peut-être prévu de te l'offrir. », « Quelqu'un a peut-être prévu de t'offrir {n} de ces articles. », « Attendre », « Je le prends quand même », « Commander quand même », « Reçu en cadeau », « Offert par une amie », « Mes amies peuvent m'offrir des articles », « Si des amies avaient prévu des cadeaux, elles ne pourront plus les voir. »).
- Prénoms : même schéma et même normalisation que les avis (`opinionNameSchema` interne → exporter un `friendNameSchema`, `opinionNameKey`), clé d'appareil `deviceKeySchema` ; une personne = un prénom normalisé sur une liste, pour les avis **et** les cadeaux (table `wishlist_opinion_devices` partagée, pas renommée).
- Occasion : 1 à 40 caractères (graphèmes), refus d'adresse web (`containsWebAddress`) ; date : `YYYY-MM-DD`, facultative.
- Limites : 30 actions cadeau / heure / appareil / liste, 120 / heure / adresse réseau / liste, avec le limiteur existant (`apps/api/src/rate-limit.ts`) ; `429` ; message « Tu as fait beaucoup de changements d'un coup. Réessaie dans un moment. »
- **Fuite interdite** : aucune route `/api/me/*` ne renvoie une ligne de `wishlist_gifts` ni un prénom d'offrante (hors `items.giftFrom`), et l'empreinte de `/api/me/changes` ne change pas quand une amie réserve, participe ou se retire.
- Jetons de design uniquement (`scripts/check-design-tokens.ts` dans `pnpm lint`) ; composants existants réutilisés ; clair et sombre ; zones tactiles ≥ 44 px (utilitaire `hit-area` existant).
- Jamais les ports 3000/3001/3100/3101, jamais `pkill -f`/`killall`, jamais `git stash` nu ; aucun secret dans le dépôt.

## Review Focus

1. Une amie réserve pendant que la fondatrice a « Mes envies » ouvert : le rafraîchissement toutes les 10 s ne doit rien changer chez elle (empreinte identique, aucune donnée nouvelle) — test en Task 3.
2. Article retiré de la liste puis remis : les réservations redeviennent normales (`item_removed_at` remis à nul), ni perdues ni doublées — test en Task 2.
3. Liste ouverte aux cadeaux **sans date** : jamais de rappel ; avec une date future : pas de rappel avant le lendemain (fuseau Europe/Paris) — test en Task 3.
4. Même prénom depuis un second appareil sans « C'est toi ? » : `409 name_taken`, pas de seconde participation ; avec `claim` : la participation existante est reprise, pas dupliquée — test en Task 2.
5. Article supprimé (corbeille, restaurable) : invisible sur le lien pour toutes, réservations gardées en base et revenues si l'article est restauré — test en Task 2.
